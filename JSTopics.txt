******************************** Design Pattern ************************************
type coercion is the process of converting one data type to another 
automatically or implicitly. This typically happens when values of 
different types are compared or operated on.

🔄 Types of Coercion
There are two types:
1. Implicit Coercion – done automatically by JavaScript.
2. Explicit Coercion – done manually by you using functions like 
Number(), String(), Boolean(), etc.

********************************Design Pattern in JS*******************************
Design patterns in JavaScript are like reusable solutions to common problems in 
code architecture. They help write cleaner, more scalable, and maintainable 
applications. Here are the most common JavaScript design patterns 👇

Module Pattern:
->Encapsulates related functions and variables to avoid polluting the global scope.
->Good for: Encapsulation, privacy, separation of concerns.

****************************Synchronous vs Asynchronous*******************************
Synchronous code in JavaScript is executed line by line, blocking further execution 
until the current operation is complete.

Asynchronous code allows operations to run in the background, enabling the program 
to continue executing other tasks without waiting for the operation to finish.

JavaScript is synchronous by default, meaning it executes code line by line, 
but it also supports asynchronous behavior through mechanisms like callbacks, 
promises, and async/await for handling tasks that take time 
(e.g., API requests, timers) without blocking the main thread.

****************************undefined vs null vs NaN***********************************
undefined: Variable declared but not assigned a value
null: null in JavaScript is a primitive value that represents the 
intentional absence of any object value. It’s explicitly assigned by 
a developer to indicate "no value" or "empty".
It's often used to reset or clear a variable.

NaN: NaN stands for "Not-a-Number" — it's a special value in JavaScript 
that represents the result of an invalid or undefined numerical operation.

*****************************Pure functions*******************************************
A pure function in JavaScript is a function whose output depends 
solely on its input arguments and produces no side effects. 
This means that for the same input, a pure function will always 
return the same output, and it will not modify any external state or variables.
 
 Pure function: 
 
 function add(a, b) {
  return a + b;
}

Impure function: 

let x = 5;

function impureAdd(a) {
  x += a;
  return x;
}

Optional chaining (?.) is a feature in JavaScript that lets you safely access 
nested properties of an object without causing an error if something is 
undefined or null.

The nullish coalescing operator (??) in JavaScript lets you provide a default 
value only when the left-hand side is null or undefined.

How does garbage collection work in JavaScript:
->Garbage Collection in JavaScript is automatic.
->It frees up memory by removing data that’s no longer used or accessible 
in your program.

How it works (behind the scenes):
JavaScript uses a strategy called "Mark and Sweep":

Mark: It starts from “roots” (like global variables, active functions, 
closures, etc.) and marks everything that is still accessible.

Sweep: It deletes everything else from memory that wasn't marked — meaning, 
it’s no longer reachable.

ex:
let user = {
  name: "Suman"
};

user = null; // The original object is no longer referenced

// 👉 JS sees it’s unreachable and deletes it from memory

->When is something garbage collected?
1. No variable or object is referencing it
2. It's not accessible from any active code

Use WeakMap and WeakSet when you want automatic garbage collection 
for keys (no memory leaks!).

Q.🔹 What is IIFE in JavaScript?
IIFE stands for Immediately Invoked Function Expression.
It's a function that runs as soon as it’s defined, without having to call it explicitly later.

Why use IIFE?
1. Avoid polluting the global scope:
It keeps variables inside a private scope, so they don't interfere with other code.

2. To run setup code once:
Useful for initializations that only need to happen once.

const config = (() => {
  const env = "production";
  const debug = false;
  return { env, debug };
})();

console.log(config); // { env: "production", debug: false }


Q. 🔍 What Happens in the Browser with a React App:
When you run a React app (e.g., from create-react-app), here’s how the browser processes it:

1. 📦 Build/Bundle Phase (before the browser even sees your code)
Before it hits the browser, tools like Webpack, Vite, or Parcel:

Bundle your files (JSX, CSS, images) into a few optimized .js files.

Transpile JSX and modern JavaScript using Babel into regular JavaScript.

The browser never sees JSX — only plain JavaScript.

2. 🌐 Browser loads index.html
React apps usually have a single HTML file (e.g., public/index.html).

This file contains a root <div id="root"></div>.

The actual content of the page is injected by React via JavaScript.

3. 📜 Browser loads bundled JS (React app)
<script src="main.js"> is in the HTML.

The browser fetches it and runs the JavaScript.

This is where React takes over.

4. ⚛️ React renders UI into the DOM
React uses:

ReactDOM.createRoot(document.getElementById("root")).render(<App />);

This tells React: “Hey, take this <App /> component and render it inside the #root div.”

React will:

Build a Virtual DOM (in memory)

Compare it with the real DOM

Apply only the necessary changes to the browser’s DOM — this is the diffing and reconciliation process

5. 🏗️ Component Lifecycle & Effects
React initializes components (useEffect, useState, etc.)

Browser continues handling JS, DOM, and rendering behind the scenes

Updates to state or props trigger re-renders, not full page reloads

6. 🧠 React handles Routing (Client-side)
If you're using React Router, navigation happens without full page reloads:

Browser intercepts link clicks

React changes the URL using history.pushState

React loads the appropriate component

The server is not re-contacted (except maybe for data)

7. ♻️ Interaction & Re-rendering
When users:

Click buttons

Submit forms

Interact with inputs

React:

Handles events

Updates state

Re-renders affected components

Browser paints updated parts of the UI
